# Подробно о безопасности {#security-deep-dive}

Для каждого соединения NATS задаёт три вопроса: кто вы, что вам разрешено и защищён ли канал. Ответим по очереди и защитим реальную нагрузку.

Это платформа заказов JetStream с тем же именем ORDERS, теперь для учётной записи, и прежними сообщениями. Один сервер перенастраивается постепенно.

## Три части безопасности {#the-three-parts-of-security}

Каждая страница относится к одной части.

**Аутентификация** определяет личность. Приложение предъявляет пароль, токен, bearer JWT либо доказывает владение секретом подписью через mTLS или NKeys, возможно с обычным JWT. Сервер решает о допуске. См. [Основы](./authentication-basics.md), [Режим оператора](./operator-mode.md), [Децентрализованная аутентификация](./decentralized-auth.md), [Auth callout](./auth-callout.md).

**Авторизация** ограничивает темы публикаций и подписок после входа; см. [Авторизация](./authorization.md).

**Шифрование** TLS защищает от прослушивания и изменения. Сертификат также может идентифицировать клиента; см. [Шифрование и TLS](./encryption.md).

## Учётная запись ограничивает область действия {#accounts-scope-all-three}

Четвёртое понятие — **учётная запись**.

Это изолированный арендатор со своими пользователями и пространством тем. Без явной связи записи не видят сообщения друг друга. [Учётные записи и многопользовательская изоляция](./accounts-and-multitenancy.md) создают две записи, [Межаккаунтный обмен](./cross-account.md) соединяет их.

Пользователь входит в запись, действует по её правам, а TLS защищает соединение.

Если явной настройки записей нет, используется глобальная `$G`.

## Результат {#what-youll-have-built}

Защитим одну платформу двумя способами с одинаковым итоговым поведением:

- ORDERS и ANALYTICS с изолированным трафиком.
- order-svc публикует только orders.>, analytics-reader читает только предоставленные заказы.
- ORDERS экспортирует orders.shipped, ANALYTICS импортирует лишь отправленные заказы.
- Та же схема под оператором ACME, которому сервер доверяет вместо списка пользователей.
- Клиентский TLS с возможностью mTLS.
- Внешний auth-svc принимает решения через auth callout.

## Предварительные условия {#prerequisites}

Понадобятся:

- nats-server, запускаемый `nats-server -c nats.conf`; сначала конфигурация меняется вручную.
- CLI nats со встроенными командами nats auth. Библиотеки передают те же данные при подключении.

Откройте терминал и конфигурацию. Начните с [Основ аутентификации](./authentication-basics.md).
