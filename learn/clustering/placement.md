# Размещение {#placement}

`ORDERS` уже работает с `R=3` в `east`, но три сервера выбрал лидер метаданных — любые с достаточным местом.

Теперь вы управляете тем, *где* находятся реплики: в определённом кластере или на серверах с назначенными метками. Это не меняет нагрузку или темы публикаций `order-svc`.

## Размещение ограничивает серверы реплик {#placement-constrains-which-servers-hold-the-replicas}

**Размещение** — правило потока, ограничивающее допустимые серверы реплик. Без него лидер метаданных свободно выбирает узлы `east`. С ним он обязан выполнить условия либо отказать в создании.

Первый рычаг — **кластер**: все реплики должны находиться в указанном кластере. Для единственного `east` это ничего не меняет. Привязка к региону в многокластерной системе разобрана в [Суперкластерах](/learn/topologies/super-clusters).

Внутри `east` важен второй рычаг — **метки**.

## Метки задаются серверам и проверяются размещением {#tags-label-servers-placement-matches-them}

**Метка** — произвольный текст в конфигурации сервера: регион, класс диска, уровень оборудования. Сервер объявляет её остальным, а размещение использует для отбора.

Метки задаются через `server_tags`. Назначьте трём рабочим серверам регион и класс диска:

```conf
# n1-east.conf — tag this server for placement
server_name: n1-east
listen: "0.0.0.0:4222"

server_tags: ["region:us-east", "disk:ssd"]

cluster {
  name: east
  listen: "0.0.0.0:6222"
  routes: [
    "nats://127.0.0.1:6223"
    "nats://127.0.0.1:6224"
  ]
}

jetstream { store_dir: "/data/n1-east" }
```

Повторите `server_tags` на `n2-east` и `n3-east`, сохраняя собственные `server_name`, порты и `store_dir`. После перезапуска проверьте результат. `nats server info` требует системную запись `$SYS`; см. [Формирование кластера](/learn/clustering/forming-a-cluster). Указывайте имя сервера, иначе ответит первый участник `$SYS` ping:

```bash
nats server info n1-east
```

Строка `Tags` показывает фактические метки. Проверяйте её: опечатка в `server_tags` остаётся незаметной до запроса отсутствующей метки.

## Несколько меток означают пересечение {#tag-matching-is-an-intersection}

Сервер подходит только при наличии *каждой* метки: `region:us-east` **и** `disk:ssd`.

Регистр не учитывается: `disk:ssd`, `disk:SSD`, `disk:Ssd` эквивалентны. Но написание должно совпадать: `disk:sdd` не подойдёт. Если метки нет, пересечение пусто, и лидер метаданных отклоняет создание. Ошибка указывает отсутствующую метку в скобках:

```
nats: error: could not create Stream: no suitable peers for placement, tags not matched ['disk:sdd'] (10005)
```

Та же ошибка возникает при запросе трёх реплик, если подходящих серверов только два. Условия не ослабляются автоматически.

Все настройки размещения и меток приведены в [справочнике](/reference/config/server_tags). Здесь нужны ограничение кластера и пересечение меток.

## Запрос лидерства выбранному серверу {#asking-a-chosen-server-to-lead}

Размещение выбирает держателей реплик, но не лидера. Начального лидера определяет слой метаданных. Поля с его именем нет: `preferred` в размещении отклоняется с `preferred server not permitted in placement`. Библиотеки тоже предоставляют в `Placement` лишь кластер и метки.

После запуска группы можно попросить текущего лидера передать роль определённому участнику через **stepdown** с предпочтительной целью:

```bash
nats stream cluster step-down ORDERS --preferred n2-east
```

Группа запускает выборы, стараясь назначить `n2-east`. Это запрос, не закрепление: итог определяет кворум. Проверьте `nats stream info ORDERS`. Для `--preferred` нужен NATS Server 2.11 или новее; синтаксис приведён в [справочнике](/reference/jetstream/api/stream).

## Типичные ошибки {#pitfalls}

Обе распространённые ошибки возникают из ожидания более мягких правил размещения.

**Отсутствующая метка обнуляет пересечение.** Вместо произвольного сервера будет `no suitable peers for placement`. Регистр `ssd` и `SSD` равнозначен, но опечатка `sdd` — другая метка. Сначала прочитайте фактические метки серверов, затем задавайте условия.

Не стройте эксплуатацию на предположении «лидер всегда `n1-east`»: после отказа его выберет кворум. Для запроса роли на определённом сервере используйте `nats stream cluster step-down --preferred

## Что уже готово {#where-you-are}

Вы пометили `n1-east`, `n2-east`, `n3-east` и ограничили `ORDERS` сочетанием `region:us-east` и `disk:ssd`. Условия образуют пересечение без учёта регистра; отсутствующая или ошибочная метка даёт `no suitable peers for placement`. Лидер задаётся не размещением, а запрашивается после создания через stepdown.

Кластер всё ещё состоит из трёх серверов: число участников не менялось.
