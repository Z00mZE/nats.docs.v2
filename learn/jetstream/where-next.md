# Куда двигаться дальше {#where-to-go-next}

В начале издатель не имел гарантированного слушателя. Теперь есть ORDERS, независимые потребители и постоянное зеркало.

Соберём модель и ссылки для продолжения.

## Основная модель {#the-core-model}

Три идеи всей главы:

**Поток** — серверный журнал. Публикация в тему сохраняется захватывающим её потоком и доступна до удаления ограничением.

Потребитель — независимый указатель чтения. Несколько читают одни сообщения с разных позиций без взаимного влияния.

Ack подтверждает обработку; без него сервер повторяет после срока. Сохранение ещё не означает обработку.

Фильтры, пулы, хранение и зеркала основаны на этих трёх понятиях.

## Где искать подробности {#where-the-details-live}

Глава не привязана к версии. Точные флаги, типы, диапазоны и стандартные значения находятся в версионируемом **справочнике**.

Начало — [корень справочника](/reference/).

## Связанные главы {#sibling-deep-dives}

Все используют ту же основу.

[Key-Value](/learn/key-value): бакет — поток, ключи — темы, история — номера, watch — потребитель. Применимы те же пределы и хранение.

[Object Store](/learn/object-store): файл делится на сообщения и собирается при чтении. Данные всё ещё в потоке.

[Кластеризация и репликация](/learn/clustering): выборы R=3, размещение и отказы подробнее одной страницы.

[Мониторинг](/learn/monitoring): уведомления, проверки здоровья и показатели отставания.

[Резервное копирование](/learn/backup-recovery): снимки, восстановление, применение [зеркал](/learn/jetstream/mirrors-and-sources) при аварии.

## Что уже готово {#where-you-are}

Новых изменений нет. ORDERS, потребители и зеркало работают. Продолжайте эксперименты или удалите через `nats stream rm
ORDERS` после завершения.

Поток хранит, потребитель читает своим темпом, ack подтверждает обработку. Это основа возможностей JetStream.

## Контрольный список перед эксплуатацией {#production-checklist}

Действия из разделов типичных ошибок со ссылками на причины.

### Ваш первый поток — см. [Типичные ошибки](/learn/jetstream/your-first-stream#pitfalls) {#your-first-stream--see-pitfalls}

- [ ] Используйте простой pub/sub, если новое заменяет старое; поток — когда пропуск имеет последствия.
- [ ] Задайте MaxAge, MaxBytes или MaxMsgs против заполнения диска.
- [ ] Выберите постоянное имя.
- [ ] Заранее решите retention: WorkQueue нельзя включить или выключить на живом потоке.

### Публикация — см. [Типичные ошибки](/learn/jetstream/publishing#pitfalls) {#publishing--see-pitfalls}

- [ ] Проверяйте PubAck, а не строку обычного nats pub.
- [ ] Задавайте стабильный Nats-Msg-Id повторяемым отправкам.
- [ ] Подтверждайте бизнес-результат обработкой, не фактом сохранения.

### Чтение — см. [Типичные ошибки](/learn/jetstream/reading-back#pitfalls) {#reading-back--see-pitfalls}

- [ ] `--all` нужен всей истории; хвост выбирается `--last`, `--since`, `--start-sequence`.
- [ ] Для возобновления нужен именованный долговременный потребитель.
- [ ] Меняйте через edit, не повторное создание.
- [ ] Различайте накопленное `--all` и новое `--new`.
- [ ] Для разового прохода добавляйте `--terminate-at-end`, иначе после очереди команда ждёт дальше.

### Доставка и подтверждение — см. [Типичные ошибки](/learn/jetstream/delivery-and-acknowledgment#pitfalls) {#delivery-and-acknowledgment--see-pitfalls}

- [ ] Ack Wait должен покрывать медленный обработчик с запасом.
- [ ] Подтверждайте успех, прекращайте неисправимое через term.
- [ ] Один ack одной доставки в одном месте.

### Фильтрация — см. [Типичные ошибки](/learn/jetstream/filtering#pitfalls) {#filtering--see-pitfalls}

- [ ] Проверяйте совпадения до вывода о пустом потоке.
- [ ] Хранение регулируют пределы, не фильтры.
- [ ] Избегайте перекрывающихся фильтров одного потребителя.

### Виды подтверждений — см. [Типичные ошибки](/learn/jetstream/acknowledgment#pitfalls) {#ack-responses-and-redelivery--see-pitfalls}

- [ ] Временный сбой — nak с задержкой; backoff регулирует тайм-ауты.
- [ ] Неисправимому сообщению сразу term.
- [ ] Слушайте уведомления MaxDeliver: встроенной dead-letter-очереди нет.
- [ ] Для долгой работы увеличьте AckWait или отправляйте in-progress.

### Pull-потребители — см. [Типичные ошибки](/learn/jetstream/pull-consumers#pitfalls) {#pull-consumers--see-pitfalls}

- [ ] Пустой fetch означает отсутствие данных сейчас.
- [ ] Задавайте expires для ограниченного ожидания.
- [ ] MaxAckPending не ниже пакета.
- [ ] Ограничивайте batch также через max_bytes.

### Масштабирование — см. [Типичные ошибки](/learn/jetstream/worker-pool#pitfalls) {#scaling-a-consumer--see-pitfalls}

- [ ] Побочные действия идемпотентны по order_id.
- [ ] Общий MaxAckPending не меньше числа обработчиков с запасом.
- [ ] AckWait соответствует реальной работе.

### Упорядоченные потребители — см. [Типичные ошибки](/learn/jetstream/ordered-consumer#pitfalls) {#ordered-consumers--see-pitfalls}

- [ ] Только для повторяемого прохода; обязательная обработка — именованный с ack.
- [ ] Работу делит пул одного потребителя; два упорядоченных читают всё каждый.
- [ ] Курсор временный, после падения проход начинается заново.

### Группы приоритетов — см. [Типичные ошибки](/learn/jetstream/priority-groups#pitfalls) {#priority-groups--see-pitfalls}

- [ ] Одна группа на потребителя.
- [ ] Переключение по min_pending или min_ack_pending: таймер failover ADR-42 ещё не реализован.
- [ ] Закрепление не блокировка: нужны ack и идемпотентность.
- [ ] expires существенно меньше pinned-ttl.

### Приостановка — см. [Типичные ошибки](/learn/jetstream/pausing#pitfalls) {#pausing-a-consumer--see-pitfalls}

- [ ] Длительность вроде 1h исключает прошедший срок.
- [ ] Рассчитывайте хранение на максимальную паузу: публикации продолжаются.

### Настройка потока — см. [Типичные ошибки](/learn/jetstream/shaping-the-stream#pitfalls) {#shaping-the-stream--see-pitfalls}

- [ ] Для обратного давления Discard New; Old молча удаляет старое.
- [ ] MaxBytes по пику, не среднему.
- [ ] MaxMsgsPerSubject разделяет квоты тем.

### Политики хранения — см. [Типичные ошибки](/learn/jetstream/retention-policies#pitfalls) {#retention-policies--see-pitfalls}

- [ ] Для перехода к/из WorkQueue создайте новый поток.
- [ ] Непересекающиеся потребители либо общий пул.
- [ ] Следите за Interest с остановленным читателем.
- [ ] Limits → Interest может удалить подтверждённую историю.

### TTL сообщений — см. [Типичные ошибки](/learn/jetstream/message-ttl#pitfalls) {#per-message-ttl--see-pitfalls}

- [ ] Проверьте Allows Per-Message TTL: иначе публикация отклоняется.
- [ ] Срок покрывает отставание исправного читателя.
- [ ] SubjectDeleteMarkerTTL нужен уведомлению об истечении; держите не больше самого короткого TTL.

### Изменение состояния — см. [Типичные ошибки](/learn/jetstream/altering-stream-state#pitfalls) {#altering-stream-state--see-pitfalls}

- [ ] Purge очищает, rm удаляет объект.
- [ ] Номера — стабильные адреса с возможными пробелами.
- [ ] Важному потоку DenyPurge и зеркало: очистку нельзя отменить.

### Отказ узла — см. [Типичные ошибки](/learn/jetstream/surviving-node-loss#pitfalls) {#surviving-node-loss--see-pitfalls}

- [ ] Проверяйте реплики перед реальными заказами.
- [ ] R=3 или R=5.
- [ ] Доказывайте переключение на настоящем кластере.

### Расширенная публикация — см. [Типичные ошибки](/learn/jetstream/advanced-publishing#pitfalls) {#advanced-publishing--see-pitfalls}

- [ ] Собирайте каждый PubAck; для порядка Nats-Expected-Last-Subject-Sequence.
- [ ] Атомарность доказывает финальный PubAck; разрыв, превышение и десять секунд тишины отменяют пакет.
- [ ] Atomic несовместим с PersistMode: async, fast-ingest совместим.
- [ ] gap: ok лишь для допустимых потерь; иначе fail или атомарность.

### Зеркала и источники — см. [Типичные ошибки](/learn/jetstream/mirrors-and-sources#pitfalls) {#mirrors-and-sources--see-pitfalls}

- [ ] Публикуйте источнику; принуждение к зеркалу даёт expected stream does not match.
- [ ] Проверяйте Lag.
- [ ] filter_subject либо subject_transforms, не оба.
- [ ] Проверяйте типы междоменных экспортов.

### Прямое чтение — см. [Типичные ошибки](/learn/jetstream/get-direct#pitfalls) {#reading-messages-directly--see-pitfalls}

- [ ] Включите Direct Get: true или allow-direct.
- [ ] Для чтения после записи используйте лидера через nats stream get.
- [ ] Для новых сообщений нужен потребитель, не прямой пакет.

### Сопоставление тем — см. [Типичные ошибки](/learn/jetstream/subject-mapping#pitfalls) {#subject-mapping--see-pitfalls}

- [ ] Сохраняйте нужные фильтрам токены `{{wildcard}}`.
- [ ] Для наверстывания нужен потребитель, не republish.
- [ ] Цель republish вне собственных тем, иначе цикл 10052.
- [ ] Историю переписывайте копированием в новый поток.
- [ ] Число разделов планируйте заранее.

### Политики — см. [Типичные ошибки](/learn/jetstream/policies#pitfalls) {#stream-and-consumer-policies--see-pitfalls}

- [ ] Storage, Persist, Deliver, Ack, Replay выбирайте до создания.
- [ ] Пересоздание требует переноса данных и сбрасывает позицию читателя.
- [ ] deliver new — однократное начало, не пропуск очереди при рестарте.
- [ ] Различайте политику и Direct Get last per subject.
