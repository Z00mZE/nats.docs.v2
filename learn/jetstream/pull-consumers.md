# Подробно о pull-потребителях {#pull-consumers-in-depth}

`shipping` выдаёт сообщение по запросу обработчика — **pull**. Ранее это означало «дай одно сообщение».

Но можно запросить несколько, обработать и вернуться либо получать непрерывно по мере поступления. Разберём оба шаблона и их ограничения.

`shipping` остаётся pull с явным ack. Меняется управляющий клиентский код.

## Два способа запроса {#two-ways-to-pull}

Библиотеки называют их одинаково.

**Fetch** запрашивает до _N_ сообщений и завершает пакет при заполнении или тайм-ауте. Обработайте конечный набор и при необходимости повторите вызов.

**Consume** поддерживает непрерывный поток. Переданная функция вызывается для каждого сообщения, библиотека фоном обновляет pull-запросы до вашей остановки.

Fetch удобен для контролируемых раундов, cron и небольших выборок обработчика запроса. Consume — для длительного сервиса, работающего по мере поступления; его используют большинство сервисов.

## Два ограничения pull {#the-two-fields-that-bound-a-pull}

Оба способа используют один протокольный запрос с полями:

- **batch** — максимум сообщений. Большой пакет сокращает обмены и повышает скорость; маленький уменьшает задержку и объём незавершённой работы при падении.
- **expires** — сколько сервер ждёт сообщения перед завершением запроса. Ограничивает ожидание тихого потока.

Библиотеки задают стандартные значения и автоматически поддерживают batch и expires для consume.

Все поля — в [Справочнике → Следующее сообщение](/reference/jetstream/api/consumer/get-next). Здесь нужны только `batch` и `expires`.

## Типичные ошибки {#pitfalls}

При реальном трафике учтите несколько настроек.

**Пустой fetch нормален.** При истечении `expires` без заказов приходит `408 Request
Timeout`, а для no-wait — `404 No Messages`. Библиотеки сообщают пустой пакет, CLI завершает с ненулевым кодом. Это отсутствие данных сейчас, не поломка: ждите и продолжайте.

     data-languages="cli,js,go,python,java,rust,csharp,c"></div>

**Сырой запрос без expires может ждать бесконечно.** Нулевой `expires` ждёт полного пакета. Библиотеки защищают стандартным сроком около 30 секунд; при нужном пределе задавайте явно. CLI использует `--timeout`.

**Малый MaxAckPending ограничивает скорость.** При лимите десять и пакете сто сервер выдаст десять и будет ждать ack. Держите предел не ниже пакета; стандарт — 1000. Он общий для всех обработчиков [пула](/learn/jetstream/worker-pool).

**Большой пакет расходует память.** `batch` считает сообщения, не байты. Для крупных заказов ограничивайте также `max_bytes` в fetch или consume: запрос завершится по первому достигнутому пределу.

## Что уже готово {#where-you-are}

У `ORDERS` и `shipping` прежнее устройство. Вы умеете получать конечный пакет или непрерывный поток, ограничивая pull через `batch` и `expires`.
